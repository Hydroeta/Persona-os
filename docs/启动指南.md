# persona-os · 本地启动指南（总控面板 + 直播链路）

> 这一份讲**顺序**：先起什么、后起什么、每步怎么判断"起来了"。
> 面板地址固定 `http://127.0.0.1:8088`；任何一步失败都只影响它自己，不会把别的拉垮。

---

## 0. 前置

| 东西 | 说明 |
|---|---|
| DSH 本体 | 插件由 DSH 加载。改完插件要**重启一次 App** 才生效（不要指望热加载） |
| Python 环境 | `ohwhale-deploy\.venv\Scripts\python.exe`（memory / painter / game-bot / audio-cover）；`index-tts\.venv\Scripts\python.exe`（IndexTTS2） |
| 模型 | IndexTTS2 权重必须在纯 ASCII 路径 `C:\idx_models` |

## 1. 启动顺序

```
① service-manager（DSH 加载时自动拉起各微服务，并开 :8010 控制口）
        ↓
② control-center（DSH 加载时自动开 :8088）
        ↓
③ live-director（DSH 加载时自动开 :9001，并把画图请求发给 painter-bridge）
        ↓
④ painter-bridge（手动起：node plugins\dsh-live-director\painter-bridge.mjs）
```

> ①②③ 都是 **bundle patch 插件**，装进 profile 后 DSH 启动即拉起，不需要单独跑。
> **④ 是独立进程**，要你自己开一个终端。

### 怎么装插件（一次性）

```
dsh plugin --profile web add "<仓库>\plugins\dsh-service-manager"
dsh plugin --profile web add "<仓库>\plugins\dsh-control-center"
dsh plugin --profile web add "<仓库>\plugins\dsh-live-director"
dsh plugin --profile web add "<仓库>\plugins\dsh-painter"
```

装完**重启一次 DSH App**。

---

## 2. 怎么判断每一步真的起来了

| 服务 | 端口 | 判据 |
|---|---|---|
| Memory | 8001 | `GET /health` 返回 200 |
| Painter | 8002 | `GET /health` 返回 200 |
| GameBot | 8003 | `GET /health` 返回 200 |
| AudioCover | 8005 | `GET /health` 返回 200 |
| IndexTTS2 | 9881 | **没有 /health**，只测端口通不通 |
| Live-Director | 9001 | WebSocket，只测端口 |
| 服务控制 | 8010 | `GET /health` → `{"ok":true,"services":[...]}` |
| 总控面板 | 8088 | `GET /health` 或直接浏览器打开 |
| painter-bridge | 9011 | `GET /health` → `{"ok":true,"service":"painter-bridge"}` |

最快的办法：**打开面板**，灯是绿的就在跑（红的就是没起，下面那行有错误原因）。

## 3. 环境变量

### 面板（dsh-control-center）
| 变量 | 默认 | 说明 |
|---|---|---|
| `CONTROL_CENTER_PORT` | 8088 | 面板端口 |
| `DANMAKU_WS_URL` | `ws://127.0.0.1:9001` | 测试台往哪发弹幕 |
| `PAINT_BOARD_PATH` | 空 | 生图浮窗读的图片（OBS 图片源那张）。**不配则浮窗一直显示"等待作画"** |
| `CONTROL_ASSETS_DIR` | `<插件>/web/assets` | 立绘等静态资源根 |
| `SERVICE_CTL_URL` | `http://127.0.0.1:8010` | 菜单里"重启/拉起"打给谁 |

### 服务控制（dsh-service-manager）
| 变量 | 默认 | 说明 |
|---|---|---|
| `SERVICE_CTL_PORT` | 8010 | 控制口端口 |
| `SERVICE_CTL_TOKEN` | 空 | 设了之后请求要带 `x-ctl-token` |

### 直播（dsh-live-director）
| 变量 | 默认 | 说明 |
|---|---|---|
| `TTS_SERVICE_URL` | `http://127.0.0.1:9881` | IndexTTS2 服务根（**不是** `/tts` 全路径，代码会自己拼） |
| `TTS_REF_AUDIO` | **自动探测** | 参考音绝对路径。**不配时自动找鲸鱼娘的 `ref_190.wav`**（见下方「参考音自动探测」），都找不到才降级 |
| `TTS_TIMEOUT_MS` | 60000 | CPU 合成一句 1~2 分钟，别调太小 |
| `TTS_WARMUP` | 开 | 设 `0` 关闭启动预热 |
| `DSH_LIVE_COLD_THRESHOLD_MS` | 120000 | **冷场阈值**（毫秒）。测试时设 `10000`，不用干等两分钟 |
| `DSH_LIVE_DIRECTOR_PORT` | 9001 | 弹幕 WebSocket 端口 |
| `OBS_WS_URL` / `OBS_SCENE_NAME` / `OBS_SOURCE_NAME` | 空 / 空 / DynamicArt | OBS 画布显隐，三个都配齐才生效 |
| `PANEL_EVENT_URL` | `http://127.0.0.1:8088/api/event` | 往面板推回复/播放状态；设空或 `PANEL_EVENT=0` 关闭 |
| `PAINTER_LOCAL_IMAGE` | 空 | 设了就用本地图当底图，不调生图 API（离线演示） |
| `PAINTER_BRIDGE_URL` | `http://127.0.0.1:9011` | 画图请求发给谁 |

### 参考音自动探测

`TTS_REF_AUDIO` 不配时，`tts.ts` 的 `resolveDefaultRef()` 按顺序探测（**只认相对用户目录的落点，不硬编码某人的绝对路径**）：

1. `$WHALE_REF_AUDIO`（显式覆盖）
2. `~/Documents/douyin-whale/out/ref_video/ref_190.wav` ← **鲸鱼娘 calm 音色**，正常会命中这个
3. `~/Desktop/新建文件夹 (2)/ohwhale-deploy/assets/voice/states/ref_calm.wav`

都找不到才打印 `[TTS降级] 未配置参考音路径（TTS_REF_AUDIO）`，**弹幕与作画照常，不崩**。

> ⚠️ 注意音色归属：`ohwhale-deploy/assets/voice/mortis/` 下那套（`default.wav` / `ref_happy.wav`）是 **mortis**，不是鲸鱼娘。要 mortis 音色就显式设 `TTS_REF_AUDIO` 指过去。

## 3.5 常见故障

### `dsh plugin` 任何子命令都报 `cannot resolve profile bundle "xxx"`

**原因**：profile 里留着某个**已被删除插件**的 link 引用。

DSH 的 profile 在 `%USERPROFILE%\.dsh\profiles\<name>\package.json`，一个插件会在**两个地方**出现：

```jsonc
{
  "dependencies": { "dsh-memory-map": "link:.../plugins/dsh-memory-map" },  // ① 依赖
  "dsh": { "profile": { "bundles": [ ..., "dsh-memory-map" ] } }            // ② bundles 数组
}
```

**只删 ① 不够，② 那条同样会让启动失败。**

**修法**：

```powershell
# 1) 先备份
$prof = "$env:USERPROFILE\.dsh\profiles\web"
Copy-Item "$prof\package.json" "$env:TEMP\package.json.bak"
Copy-Item "$prof\pnpm-lock.yaml" "$env:TEMP\pnpm-lock.yaml.bak"

# 2) 用编辑器把两处都删掉，然后
dsh plugin --profile web install

# 3) 验证：能正常列出包就算修好
dsh plugin list --profile web
```

### 冷场不触发

先确认 `DSH_LIVE_COLD_THRESHOLD_MS` 有没有生效；再确认 `director.markInteraction()` 是不是被频繁调用（**任何一条弹幕到达都会重置冷场计时**，包括你自己在面板里发的）。

### TTS 不出声但不崩

看日志里的关键字：

| 日志 | 含义 |
|---|---|
| `[TTS降级] 未配置参考音路径` | 自动探测没命中，显式设 `TTS_REF_AUDIO` |
| `[TTS降级] 播放失败` | `:9881` 没起，或返回的不是 wav |
| `[TTS降级] 超时` | CPU 合成慢，调大 `TTS_TIMEOUT_MS` |

**这些降级都只影响声音，弹幕、作画、面板联动全部照常。**

## 4. 体验一条完整链路

1. 面板里输入 `!画 像素风的猫` → 右边出现"我发的"，同时服务端回包。
2. 弹幕进队列 → director 判断是画图单 → **面板事件通道**推 `paint_start` → 立绘闪。
3. painter-bridge 收请求 → 生图 → 像素化 → 逐帧写 `PAINT_BOARD_PATH` → 浮窗自动弹出逐帧播放。
4. 画完推 `paint_end`；如果有 TTS，`tts_start` / `tts_end` 会让立绘闪/停。
5. 她的回复文本会以 `『鲸鱼娘』` 前缀出现在面板弹幕流里（走 `chat_reply` 事件）。

## 5. 现在**还缺**的东西（别期待它自己好）

| 缺 | 表现 | 补法 |
|---|---|---|
| IndexTTS2 没起 | 面板正常，但**不出声**，日志 `[TTS降级] 播放失败` | 起 `indextts_server.py` |
| `TTS_REF_AUDIO` 没配 | 同上，日志 `未配置参考音路径` | 配环境变量 |
| painter-bridge 没起 | 发 `!画` 会 `fetch failed`，浮窗一直"等待作画" | `node painter-bridge.mjs` |
| `PAINT_BOARD_PATH` 没配 | 浮窗永远空 | 指到 OBS 图片源那张图 |
| OBS 没开 / 设了密码 | 画布不显隐（只打日志） | 开 OBS 并清空 websocket 密码；**sha256 认证尚未实现** |
| 聊天靠 LLM | 没有 `dsh-llm-router` 时回复是 mock 文案 | 装 router 或接受 mock |
